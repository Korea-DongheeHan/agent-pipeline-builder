아래는 태스크 입력이다.)

## 요구사항
{{vars.requirement}}

## 작업
1. 요구사항의 영향 모듈(도메인/애플리케이션/API 등)을 분석하고 구현 계획을 세워라.
2. 스펙 초안을 작성하라: 범위(포함/제외), GWT 시나리오, 불변식·계약,
   **acceptance 기준(`A1, A2, ...` ID 부여)**, 가정.
3. 작업을 레이어별로 분해하되, 후속 두 갈래가 병렬로 진행할 수 있게
   인터페이스(시그니처·타입)를 확정하라:
   - **구현 갈래** (implement 노드): 도메인 → 코어 → 애플리케이션 → 배포 모듈
   - **테스트 갈래** (test 노드): 확정 인터페이스 기준 단위 테스트 선행 작성

## 주의 (그래프 실행 모드)
이 실행은 headless 라서 사용자에게 질문할 수 없다(스펙 게이트 없음).
미확정 사항은 코드·컨벤션 기준으로 결정하고 반드시 "가정" 절에 남겨라 —
사용자가 실행 후 가정을 검토한다.

## 판정
분석·스펙 초안 완성 시 SUCCEEDED, 요구사항이 모순·구현 불가면 FAILED.
